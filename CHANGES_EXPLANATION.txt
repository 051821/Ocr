CLINICAL NLP & LONGITUDINAL ANALYSIS OVERHAUL - EXPLANATION OF CHANGES
================================================================================

OVERVIEW
--------------------------------------------------------------------------------
Per your requirement:
1. LLM has been completely removed from the Clinical NLP and Entity Extraction stage.
   The local Ollama model (qwen3:4b) is now ONLY called at the very final stage
   when generating the narrative report from pre-computed, verified structured JSON.
2. The deterministic NER, regex, and clinical extraction engine has been overhauled
   to reliably handle diverse medical reports without relying on an LLM:
   - Complete Blood Count (CBC)
   - Serum Biochemistry / Liver Function / Kidney Function / Electrolytes
   - Urine Routine Examination (both quantitative values and qualitative observations)
   - Handwritten / Printed Prescriptions (catching all medicines, OCR errors, and supplements)
3. False-positive diagnoses and erroneous numerical trends have been eliminated.


DETAILED BREAKDOWN OF CHANGES BY MODULE
================================================================================

1. CLINICAL NLP EXTRACTION (clinical_nlp/)
--------------------------------------------------------------------------------
* clinical_nlp/events.py:
  - Removed 'from clinical_nlp.lllm_extraction import extract_with_llm'.
  - Removed the LLM fallback extraction loop entirely.
  - Added reference/guideline text exclusion: Any entity appearing inside educational
    or reference text (e.g. "Alkaline Phosphatase may indicate liver disease...")
    is filtered out so it never becomes a patient clinical finding.
  - Added support for qualitative findings (e.g., 'ABSENT', 'CLEAR', '0-1 /HPF').

* clinical_nlp/medications.py:
  - Added line pre-processing (_preprocess_med_line) to split OCR-concatenated tokens
    (e.g., 'ealciumd31000mg' -> 'ealcium d3 1000 mg').
  - Expanded dosage form prefix regex (_DOSAGE_FORMS) to handle OCR misreadings
    ('tab', 'cap', 'inj', 'syp', 'ab', 'ao', 'tb', 'ta', 't.', 'c.').
  - Added Pass B (_MED_NO_DOSE_RE) for prescription lines that omit numeric dosage
    (e.g., 'ab b complex od', 'cap vitamin d3 weekly').
  - Expanded frequency code patterns (_FREQ_ALTS) to recognize OCR corruptions
    such as 'bbr' -> 'twice_daily' (bd), 'bbd', '1-0-1', '1-0-0', '0-0-1', 'hs', 'sos'.
  - Result: All 7 medications from Patient 1 (Amlodipine, Telmisartan, Metformin,
    Aspirin combo, Tramadol, Calcium + Vitamin D3, Vitamin B Complex) are now extracted!

* clinical_nlp/labs.py:
  - Overhauled into a robust multi-pass deterministic extractor:
    * Pass 1: Same-line extraction with mandatory units and reference intervals.
    * Pass 2: Columnar, multi-line, and qualitative extraction. Handles OCR layouts
      where the result appears on the line below with a colon (e.g. ': ABSENT',
      ': 9ML', ': CLEAR', ': Yellow', ': 6.5', ': 1.005', ': 0-1 /HPF').
  - Contextual awareness: When 'URINE' or 'URINE ROUTINE' is present in the document,
    ambiguous terms like 'Albumin', 'Glucose', 'Blood' are automatically mapped
    to their Urine-specific counterparts ('Urine albumin', 'Urine glucose', 'Urine blood').
  - Position de-confliction: Prevents 'Blood urea' from claiming the same line
    as 'Blood urea nitrogen', resolving the false downward Urea trend bug.
  - Backward search: Captures columnar values where results precede headers
    (e.g., ':3.96 3.5-5.2 \n Serum Albumin' correctly extracts Albumin = 3.96 g/dL).
  - Physiological sanity bounds: Filters out registration and address codes
    (e.g., prevents 'LSnop No 30' from being misidentified as 'Albumin: 30.0').

* clinical_nlp/diagnoses.py:
  - Replaced substring search with strict whole-word regex boundary (\b) matching.
    This permanently prevents 'oa' from matching inside words like 'investioation'.
  - Added reference text filtering: Entities in guideline/reference sentences
    ('may indicate River disease or certain bone disorders') are ignored.

* clinical_nlp/assertion.py:
  - Added 'is_in_reference_text(text, start, end)' helper function to detect
    sentences containing educational triggers ('may indicate', 'seen in', 'reference:',
    'ADA guidelines') and prevent them from generating patient diagnoses.
