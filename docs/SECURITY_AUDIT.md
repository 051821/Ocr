# Security Audit: Clinical Record Analytics & Dashboard

| Finding | File:Function | Risk | Why | Proposed Fix | Effort | Could it change behavior? |
| :--- | :--- | :---: | :--- | :--- | :---: | :---: |
| **a) API key sourced from plain config.py import** | `dataanalysis/core/config.py:12-17`, `config.py:262-266` | **High** | Sourcing keys via file import (`from config import OPENROUTER_API_KEY`) risks accidental commits and static exposure if `.env` or files leak; un-sanitized keys could be exposed in runtime traceback dumps. | Source exclusively via `os.environ.get("OPENROUTER_API_KEY")` or an isolated secret manager; deprecate static config import; fail gracefully if unset. | S | N |
| **b) patient_id and question text written to logs/patient_chat.log** | `dataanalysis/patient_chat.py:995-1010` (`answer_patient_question`) | **High** | Audit logger writes raw `patient_id` and query strings (`question`) in plaintext to `logs/patient_chat.log`. Queries frequently contain sensitive PHI and identifiers, violating HIPAA minimum necessary rule and creating an unencrypted PHI store. | Replace raw `patient_id` with salted hash `hmac_sha256(patient_id, salt)`; strip/mask free-text query or log only question intent/token count and classification category. | S | N |
| **c) Clinical prompts and responses stored in plaintext in llm_cache SQLite table** | `dataanalysis/storage/ai_analysis_csv.py:49-53`, `dataanalysis/core/llm_client.py:76` | **High** | Full LLM completion payloads containing patient notes, diagnoses, medications, and labs are stored in unencrypted SQLite (`data/cache.db`). If local file permissions are broad, any local user or backup tool can read raw PHI. | Store only SHA256 hashed keys; encrypt SQLite cache values at rest (e.g. using AES-GCM / SQLCipher) or redact PHI before caching; implement automatic TTL/cache eviction. | M | N |
| **d) ":free" model in fallback list in core/config.py** | `dataanalysis/core/config.py:9-10` (`DEFAULT_MODELS`) | **High** | Third-party free OpenRouter endpoints (`inclusionai/ling-3.0-flash-sante:free`) typically log prompts for training/evaluation and offer zero HIPAA BAA or security guarantees, exposing clinical data to public AI aggregators. | Remove `:free` model completely from default model lists. Enforce an approved commercial/enterprise tier allowlist with BAA commitments. | S | N |
| **e) Clinical facts sent to third-party LLM with no de-identification** | `dataanalysis/Zai_analysis.py:36-70`, `dataanalysis/patient_chat.py:905`, `dataanalysis/analysis.py:880-888` | **High** | Raw clinical dates, visit IDs, lab numbers, and notes are transmitted directly to external cloud LLM APIs without tokenization, pseudorandom ID masking, or date-shifting. | Implement a pre-call de-identification adapter: pseudonymize patient IDs, relative-shift dates (e.g., Encounter Day 0, +14d), mask names/phone numbers before egress, and restore upon return. | M | Y (if token substitution changes prompt semantics; must be feature-flagged) |
| **f) unsafe_allow_html rendering of text derived from OCR/DB** | `dataanalysis/app.py:818`, `dataanalysis/ui_components.py:380-407` | **Med** | One confirmed unescaped site: `app.py` `ch_text` rendered via `unsafe_allow_html` in the medication-journey tab; other sites to be audited; `render_field` and most of `ui_components` already use `html.escape`. | Wrap `ch_text` and any remaining unescaped dynamic variables in `html.escape()` or dedicated escaping helper before string interpolation in `st.markdown(..., unsafe_allow_html=True)`. | S | N |
| **g) Prompt injection through OCR text in LLM prompts** | `dataanalysis/analysis.py:887` (`_ai_extract_full_clinical_summary`), `dataanalysis/patient_chat.py:905` | **High** | Untrusted OCR text extracted from scanned patient records is concatenated directly into LLM prompts without delimiter sandboxing or system boundary defenses; malicious documents can instruct the LLM to ignore system instructions or leak records. | Enforce XML-style encapsulation (`<clinical_record>...</clinical_record>`), instruct the LLM to ignore meta-instructions within delimiters, and validate strict JSON schema / regex on model outputs. | M | N |
| **h) Chat answers not passing the output sanitizer reviews use** | `dataanalysis/patient_chat.py:909` | **High** | `review_rules.py` runs `sanitize_review()` to strip imperative prescribing verbs (`prescribe`, `increase dose`, etc.) and enforce disclaimers, but chat responses bypass this sanitizer and output directly to the clinician/user. | Route all LLM chat answers through `review_rules.py`'s imperative filter and safety validator before rendering. | S | Y (blocks unsafe prescription recommendations generated by LLM chat) |
| **i) No authentication or per-user patient access control** | `dataanalysis/app.py` (top-level entry) | **High** | The Streamlit dashboard allows any network client who reaches port 8501 to browse all patient IDs and histories in PostgreSQL without user login, role checks, or session verification. | Introduce an authentication gate (OIDC/OAuth2/session middleware or Streamlit Auth) with Role-Based Access Control (RBAC) ensuring users are authorized to inspect clinical data. | M | Y (unauthenticated sessions will be redirected to login) |
| **j) No audit trail of who viewed which patient** | `dataanalysis/app.py:586` (`fetch_patient_history`), `dataanalysis/analysis.py:965` | **High** | Clinician access and record viewing are completely unrecorded; impossible to determine who accessed which patient chart or identify unauthorized record snooping under HIPAA audit standards. | Log every chart fetch with authenticated user ID, tenant, client IP, patient ID hash, timestamp, and purpose of use to an immutable, append-only security log table/file. | S | N |
| **k) Parameterization check across SQL queries** | `dataanalysis/analysis.py:973-1053`, `database.py`, `dataanalysis/core/db.py` | **Low** | Core clinical history query uses parameterized `%s::uuid` (`(patient_id,)`). However, defensive validation of UUID formatting before SQL execution is missing, and read-only connection enforcement is purely administrative. | Validate UUID format using `uuid.UUID()` before DB query; set PostgreSQL session or role to `READ ONLY` (`SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY;`). | S | N |
| **l) Neo4j credential and driver handling** | `dataanalysis/neo4j_client.py:47-51` | **Low** | Neo4j credentials are read dynamically across 4 env var aliases; if driver initialization fails, plaintext errors can propagate. Clear disconnect/lifecycle teardown hooks on process shutdown are omitted. | Standardize environment variable names (`NEO4J_URI`, `NEO4J_USER`, `NEO4J_PASSWORD`); implement a graceful shutdown cleanup hook (`driver.close()`); ensure connection pooling metrics. | S | N |
| **m) Unpinned dependencies** | `requirements.txt` | **Med** | Core packages (`requests`, `rapidfuzz`, `spacy`, `boto3`, etc.) are completely unpinned without version constraints or SHA256 hashes, risking supply chain attacks, breaking API changes, or compromised wheels. | Pin exact versions in `requirements.txt` and generate a cryptographically locked `requirements.lock` / `pip-tools` compile file. | S | N |
| **n) Raw exception text shown in the UI** | `dataanalysis/app.py:540, 591, 934, 1014` | **Med** | Unhandled database or API exceptions display raw error strings (`st.error(f"Database connection error: {e}")`), revealing database connection hostnames, schema details, or network paths. | Replace UI errors with sanitized user-friendly messages ("A secure connection error occurred. Reference ID: <uuid>"); log the detailed trace only to secure system logs. | S | N |
| **o) Cache and log retention and file permissions** | `dataanalysis/storage/ai_analysis_csv.py`, `dataanalysis/patient_chat.py:27-35` | **Med** | `patient_chat.log` and `data/cache.db` are created with default OS file permissions (world-readable on shared environments) without automatic retention cleanup or max storage quotas. | Set strict file creation masks (`os.chmod 0600`), define retention pruning jobs (e.g., 30-day purge for cache/chat logs), and ensure logs are stored outside web roots. | S | N |
| **p) Chat prompt vs review prompt contradictions** | `dataanalysis/patient_chat.py:47-65`, `dataanalysis/Zai_analysis.py:20-33` | **High** | AI Review strictly forbids outside knowledge and speculation ("Analyze using only supplied records... Never invent facts"), whereas Chat explicitly encourages external pharmacologic/lifestyle knowledge ("list established clinical side effects from pharmacology knowledge", "Lifestyle advice"). | Harmonize policy: establish a shared foundation prompt defining that external knowledge is strictly limited to standard reference pharmacology/lifestyle, never overrides patient history, and cannot offer speculative medical diagnoses. | S | Y (aligns chat outputs with core clinical safety boundaries) |
| **q) Shared in-memory cache across sessions** | `dataanalysis/app.py` (`@st.cache_data(ttl=300)`) | **Med** | `st.cache_data(ttl=300)` in `app.py` keeps full patient records in server memory shared across sessions. Without authentication or per-user cache partitioning, memory-dump or state leakage across browser sessions is possible. | Shorter TTL and/or per-user cache key once authentication exists. | S | N |
| **r) Uncontrolled multi-vendor LLM fallback chain** | `dataanalysis/core/llm_client.py:49-82`, `core/config.py:5-10` | **Med** | The LLM fallback chain can iterate through multiple candidate models on failure, potentially sending a single clinical prompt across up to four distinct vendors/providers. | Restrict to strict allowlist with minimal fallback targets from vetted providers. | S | N |
| **s) Residual SQLite cache retention after Postgres patient deletion** | `dataanalysis/storage/ai_analysis_csv.py` (`data/cache.db`) | **Med** | Deleting or expunging a patient record from PostgreSQL does not automatically invalidate or purge cached prompts, responses, or reviews stored in `data/cache.db`. | Provide a purge-by-patient maintenance command (SQLite only) to delete records from `ai_review`, `chat_faq`, and `llm_cache` when a patient is purged. | S | N |
